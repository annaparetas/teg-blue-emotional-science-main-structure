# What Is TEG-Blue — foundation library for the rebuild

This folder holds the foundation concepts the rebuild works from: what TEG-Blue is, why it exists, the premises that make it TEG-Blue, and the posture and ethics that constrain every page. It exists so that Anna and any session working in this workspace can answer *what are we doing and how* without excavating the accumulated `teg-blue/` material.

It is a selective, traceable carry from `../../../teg-blue/what-is-teg-blue/`, following the migration policy in the [repository README](../../../README.md). Nothing was copied wholesale. Every file here says where it came from and what role it plays now.

## The two rules of this folder

1. **Each carried file opens with a carried note.** The note names the source, the role here (governing or provenance), and any terminology the rebuild has since superseded. The body below the divider is Anna's original text, unchanged.
2. **Changes to a concept are decisions, not edits.** If the rebuild changes what one of these files says, record the decision in `development/decisions/` or `development/registers/` and then update the file here deliberately, noting it in the carried note. The original in `teg-blue/what-is-teg-blue/` keeps serving the public-site work; divergence between the two folders should always be on purpose.

## Terminology bridge

The carried files predate the rebuild's 19 August 2026 terminology pass. The [Project Terminology Ledger](../../../GLOSSARY.md) governs current wording. The main deltas when reading here:

| In the carried files | In the rebuild |
| --- | --- |
| `acute` | **Fluid organisation** — present-responsive organisation that remains coupled to current conditions and updating. `Acute` remains in historical material. |
| `chronic`, `stuck`, `chronically online` | **Chronic organisation**, bounded: recurrent narrowing, generalisation, persistence or difficult revision — not continuous activation, permanence, or diagnosis. Several routes, not one (`Chronic routes`). |
| Formation working names (Control / Management, Domination) | C **Strategic Management**, D **Power Mobilisation** in Engine 2; renames for C and D are still open in the ledger. X Baseline, A↔B Safety Checking and Z Shutdown have no ancestor in the visual layer. |
| ESS = Embodied Somatic System (older expansion) | ESS = **Emotional Somatic System** — divergence recorded in the ESS/CLS decision note, kept for later resolution. |
| `nervous-system state` used freely | Prefer `response pattern` or `organisation` unless a study operationalises a state. |

The ledger's retired-claims table also applies when quoting older material: no body-energy-strategy, no accumulation-at-A, no restoration-only-at-X, no one-emotion-one-chemical, no amygdala-takes-over.
